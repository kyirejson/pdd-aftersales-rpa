# 安全边界

## 默认安全姿态

发布版配置默认处于：

- `execution_mode = observe`：观察和诊断优先，禁止外部写操作；
- `live_actions_enabled = false`：真实外部动作总开关关闭；
- 千牛生产流程、售后工作台生产提交、钉钉同步和消息平台均未启用；
- 店铺、仓库、群组和内部文档 URL 均为占位符。

即使代码中存在退款、消息和登记能力，也必须同时通过模式、总开关、身份核验和审批门槛后才会真正执行。

## 身份与窗口核验

高风险动作执行前会核验：

- 店铺 ID 与店铺显示名；
- Edge Profile 与浏览器用户目录；
- 页面 URL 与窗口标题；
- 目标客户端窗口是否处于前台；
- 消息群组是否在白名单中；
- 工作进程是否仍属于当前受控任务。

任何一项无法证明时，物理输入会被拒绝。

## 审批与状态机

- 规则可以声明 `approval_required`；
- 状态机限制采集、规则匹配、审批、执行、核验和完成之间的迁移；
- 人工可把任务标记为待复核、拒绝、暂停或恢复；
- 外部写入结果不确定时，不允许自动视为成功。

## 幂等与恢复

- 任务使用店铺、订单、售后单和动作类型构成业务键；
- 外部动作使用幂等键登记，避免重复退款或重复发送消息；
- 重启后只恢复未完成内部步骤，不重复已验证成功的外部写动作；
- 连续失败会触发熔断和全局暂停。

## 本地敏感信息

以下内容一律不提交仓库：

- `config/settings.json` 真实生产配置；
- `runtime/rpa.db` 业务数据库；
- `runtime/console_access.json` 控制台密钥；
- `runtime/evidence/` 截图和证据；
- 浏览器用户目录、Cookie、登录态和 DPAPI 数据；
- 任何真实订单、客户、电话、地址或内部文档链接。

`.gitignore` 已排除上述路径。生成界面截图前也应使用合成任务，不使用生产数据库。

## 生产启用前清单

1. 明确代码和业务规则已经获得对外展示或运行授权；
2. 复制 `settings.example.json` 为本机配置，不直接提交真实配置；
3. 完成店铺 Profile、ERP、消息平台、快递和登记表的只读验收；
4. 逐个启用消息组件并核验白名单群组；
5. 先运行 observe，再运行 approve，最后才考虑 auto；
6. 设置全局暂停、失败熔断、最大金额限制和人工审批；
7. 确认源环境已停止，避免两个执行端同时操作；
8. 定期备份 SQLite，并演练恢复和回滚流程。

## 凭据处理

- 控制台密码使用 PBKDF2-HMAC-SHA256 和随机盐哈希保存；
- 会话密钥只保存在本机运行目录；
- 圆通凭据使用当前 Windows 用户 DPAPI 或 Windows 凭据管理器保存；
- 仓库中不得出现明文密码、Cookie、Token 或浏览器登录态。
