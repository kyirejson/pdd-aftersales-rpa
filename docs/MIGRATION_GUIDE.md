# 拼多多/千牛售后 RPA 跨电脑迁移说明

本说明适用于迁移包格式 v2。迁移目标是把当前代码、业务数据库一致性快照、证据文件和离线安装环境完整复制到另一台 Windows 电脑，同时确保新电脑在人工验收前不能自动执行业务动作。

## 先确认迁移边界

1. 迁移包包含业务订单、动作审计和截图证据，按敏感业务资料保管；不要上传公共网盘或交给无关人员。
2. Edge、千牛、圆通、钉钉、微信、企业微信和旺店通的登录态可能受 Windows DPAPI、设备指纹或客户端本机保护，迁移包中的机器绑定备份只用于留档，不用于直接恢复登录。
3. 圆通账号密码的 DPAPI 密文明确不进入迁移包；新电脑必须重新配置。
4. 部署数据库已强制设置为 `global_paused=true` 且运行状态为 `STOPPED`。源项目的生产配置仍可能允许真实动作，因此不得跳过全局暂停检查。
5. 源电脑与新电脑绝对不能同时开启正式自动执行。正式切换必须有唯一操作人和明确切换时间。

## 迁移包结构

- `project/`：当前可部署代码、测试、配置、暂停状态数据库和历史证据；
- `offline/`：Python 3.13.14 x64 安装包及锁定的 Python wheel；
- `machine_bound_backup/`：源电脑数据库原始只读快照及浏览器目录留档，不自动部署；
- `diagnostics/`：源电脑日志和迁移辅助信息；
- `MIGRATION_MANIFEST.json`：环境、配置摘要、数据库统计、版本差异和复制告警；
- `SHA256SUMS.txt`、`SHA256SUMS.sha256`：文件级完整性校验；
- `版本变更清单.md`：相对上一版清单的完整增删改文件；
- `迁移包内容清单.md`：各区文件数、大小和数据库快照摘要；
- `迁移验收清单.md`：安装、账号、只读、切换的逐项签字表；
- `回滚操作手册.md`：失败判定和恢复源电脑的操作顺序。

## 一、复制与完整性校验

1. 把整个迁移包或 ZIP 复制到新电脑本地 NTFS 磁盘，例如 `D:\PDD_RPA_Migration_...`。
2. 不要从 ZIP 内部、U 盘、共享目录、OneDrive 同步目录或只读介质直接运行。
3. 如收到 ZIP，先核对 ZIP 旁的 `.zip.sha256`，再完整解压。
4. 在迁移包根目录双击 `00_校验迁移包.cmd`。
5. 只有看到“SHA-256 全部匹配”才能继续；任何缺失、无法读取或摘要不匹配都必须重新复制。

完整性校验用于发现复制损坏或文件变动，不是数字签名，不能替代可信传输渠道。

## 二、安装基础环境

在迁移包根目录双击：

```text
01_安装迁移项目.cmd
```

安装器会依次完成：

1. 再次校验迁移包；
2. 检查或离线安装 Python 3.13 x64；
3. 新建 `.venv`，不复用源电脑虚拟环境；
4. 从 `offline/wheelhouse` 安装锁定依赖；
5. 重写数据库内的旧绝对路径；
6. 识别以完整店铺名命名的拼多多 Edge Profile；
7. 创建圆通、钉钉和千牛独立浏览器目录；
8. 再次强制全局暂停并运行项目初始化与全量测试；
9. 生成 `project\runtime\migration_preflight.json`；
10. 安装 8876 控制台守护进程。

首次安装时预检返回“基础环境已就绪、尚未满足正式切换”是正常现象，因为账号和人工只读验收尚未完成。

## 三、安装桌面软件并固定环境

新电脑需要安装并登录：Microsoft Edge、旺店通 ERP 旗舰版、企业微信和微信。建议与源电脑保持相同的 1920×1080、100% 缩放；若实际源环境不同，以 `MIGRATION_MANIFEST.json` 中记录为准。

运行期间不要锁屏、切换 Windows 用户、最小化远程桌面会话或让弹窗长期遮挡业务窗口。先完成系统更新、Edge 更新及客户端更新，再做坐标和组件验收。

## 四、建立 11 家拼多多 Edge Profile

每家店铺必须使用普通 Edge 中一个独立 Profile，并把显示名称设置为完整店铺名：

1. 示例书店 A
2. 示例书店 B
3. 示例书店 C
4. 示例书店 D
5. 示例书店 E
6. 示例书店 F
7. 示例书店 G
8. 示例书店 H
9. 示例书店 I
10. 示例书店 J
11. 示例书店 K

逐店登录拼多多商家后台后运行：

```powershell
Set-Location <迁移包>\project
.\.venv\Scripts\python.exe scripts\prepare_migrated_machine.py
```

脚本按显示名称重绑 Profile，目录编号不需要与源电脑相同。随后在控制台打开全部拼多多窗口，逐店确认 Edge Profile 显示名、页面店铺名和配置店铺名三者完全一致，并只读扫描列表与详情页。

## 五、建立千牛独立 Profile

千牛使用 `project\runtime\edge_profiles\qianniu_edge`，不与 11 家拼多多 Profile 混用。

1. 在控制台打开千牛窗口；
2. 在该独立窗口登录“示例天猫旗舰店”；
3. 打开未收货退款列表；
4. 确认店铺名称、列表 URL 和独立窗口身份正确；
5. 只做扫描、详情读取和旺店通只读查询，不点击拦截、同意退款等真实动作；
6. 在验收清单记录测试售后单号与证据路径。

## 六、圆通与钉钉独立配置

### 圆通客户管家

1. 运行 `.\.venv\Scripts\python.exe -m pdd_rpa.cli configure-yto-login`，在新电脑当前 Windows 用户下重新录入账号密码；
2. 在控制台打开圆通独立窗口；
3. 如出现图形验证码，人工完成一次；
4. 确认进入 `/new/home`、群名精确匹配，并完成不发送消息的定位与回读预检。

不要把 `machine_bound_backup\edge_profiles` 覆盖到项目运行目录。

### 钉钉在线表格

在控制台打开钉钉 Playwright 独立窗口并重新登录，逐一核验配置中的两个目标：

- 示例自营仓：`快递拦截丢件登记表(示例自营仓)` / `2026`；
- 示例代发分销：配置中指定的在线表格 / `2026登记`。

两张表都要验证文档、工作表、列布局、查重和行定位；迁移预检阶段不得写入业务记录。

## 七、旺店通与消息平台只读验收

至少选择一张已发货订单进行旺店通只读查询，确认订单号、原始平台单号、订单状态、仓库、物流公司、运单号和商品名称均可读取，且查询没有业务写入。

逐一验证数据库/配置中的消息白名单目标：

- 企业微信：中通、顺丰以及各供应商群；
- 微信：韵达群；
- 圆通：专属客户服务群。

验收时只做群搜索、精确命中、窗口身份、发送前预览及既有消息回读。若必须测试真实发送，应使用明确的测试内容并由负责人单独批准，不得把测试发送当作迁移预检的默认步骤。

## 八、填写人工验证记录并重新预检

把 `project\docs\migration_validation.template.json` 复制为 `project\runtime\migration_validation.json`。只有实际完成对应检查后才能把字段改为 `true`，不得沿用源电脑旧报告。

完成记录后运行：

```powershell
.\.venv\Scripts\python.exe scripts\migration_preflight.py
```

切换前的第一次报告必须满足：

- `ready_for_console=true`；
- 数据库 `integrity=ok`、`global_paused=true`、`runtime_state=STOPPED`；
- 11 店、千牛、圆通、钉钉两个目标、旺店通和消息白名单全部通过；
- `business_action_performed=false`；
- 除 `source_stopped_and_cutover_approved` 外的人工检查全部通过。

此时 `ready_for_live_cutover=false` 是预期结果，因为源电脑尚未正式停止。不要为了让报告变绿而提前填写切换批准字段。

## 九、正式切换

1. 记录源电脑和新电脑的最终数据库时间、负责人及计划切换时间；
2. 保持新电脑全局暂停，完成一整轮 11 店加千牛只读扫描；
3. 停止源电脑控制器和守护进程，确认不再产生新日志或数据库写入；
4. 再次确认网络中不存在第二个执行端；
5. 在 `migration_validation.json` 填写 `source_stopped`、`single_executor_confirmed`、批准人和批准时间；
6. 再次运行 `migration_preflight.py`，必须得到 `ready_for_live_cutover=true`；
7. 在新电脑解除全局暂停；
8. 人工监控至少一整轮，逐项检查动作日志与截图证据；
9. 验收稳定后再进入无人值守，并保留源电脑和迁移包直至观察期结束。

## 十、异常与回滚

出现店铺/Profile 不一致、消息群误命中、窗口错位、数据库异常、重复执行端、证据缺失或任何不确定业务动作时，立即保持/恢复新电脑全局暂停并停止控制器。随后按根目录 `回滚操作手册.md` 恢复源电脑。

路径重写前的数据库副本位于：

```text
project\runtime\migration_backups\rpa.before_machine_rewrite.*.db
```

迁移包根目录的 `machine_bound_backup\database\rpa.source_snapshot.db` 是打包时的原始一致性快照，必须保持只读留档。
